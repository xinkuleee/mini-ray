## What is measured

1. **Wire bytes at real callback crossings.** `transport.py:208–210` uses `transport._pickler.dumps(..., protocol=pickle.HIGHEST_PROTOCOL)`, preferring cloudpickle (`:39–41`). Record this actual serializer and protocol for both variants. Measure each actual request DTO and returned reply DTO; also measure the real business RPC envelope (`_WireRequest(handler, payload)` at `:841`, `_WireReply(ok=True, value=reply)` at `:687`). Report frame length separately: `_encode` adds four bytes to the business frame (`:232–241`). No `sys.getsizeof`, approximate JSON length or stale prototype pickle counts.
2. **Unknown replies.** Count every request attempt, generated reply, delivered reply and intentionally discarded reply separately. A real accepted reply lost before its client ACK still contributes server-generated bytes and copy cost. A before-effect transport failure contributes no server reply. Do not replay an extra request just to collect data.
3. **Copy/validation calls.** Under explicit boundary labels, profile actual `_copy`, concrete `__post_init__`, `_validate_snapshot`, `_validate_prepared` and `_validate_closed` calls. Record construction counts by actual value type, including full publication/manifest/prepared/Complete/ClosedContainedHolds. Report `_copy` invocations and constructor calls separately; neither is a byte count or elapsed-time claim. Auditing serializer and observation calls are suspended from the business-copy profile.
4. **Repeated content.** An audit-only structural walk of the actual DTO counts full publication/manifest/prepared/Complete/closed-hold references by field path and by object identity. Count repeated paths as logical duplication and unique identities separately (pickle memoization can share identities). Do not assign the standalone serialized size of a nested object additively to the envelope; pickle memoization makes that false. The serializer length of the actual envelope is the wire result.
5. **Queries/RPCs.** Tag business GCS RPC, existing internal controller query, child/Node/owner callback and test-only observation query separately. Runtime extra query count contributes to candidate cost; test-only query adaptation is reported as test observation, not hidden as a free production query or compared as business overhead. Trace never adds a network query.
6. **Structure.** Raw diff, changed files, added/removed type and field names, authority state fields, `if`/exception branches and actual caller-to-authority reading path. AST counts plus a short manual explanation distinguish necessary strict wire type branches from new runtime state. Test/document reductions are not runtime savings.

The standard-library-only `cost_capture.py` is an inert helper for recording numbered events, byte sizes from caller-supplied serializers and profiled constructor/validation counts. A later driver must supply actual runtime methods and complete lifecycle assertions; the helper cannot run the project, invent replies or claim a passed trajectory. Trace sidecar bytes are excluded from deterministic business-wire comparison and identified separately; same-version seven-main trace validation still runs if adopting.

## Decision

Adopt only if the complete candidate paths and affected contracts pass, no new authority/synchronization appears, and measured whole-lifecycle reduction is not canceled by fact duplication/copy/query/error complexity. Successful smaller DTO pickle length alone is insufficient.

Retain current E only with the actual candidate diff, fixed input, real runs and cost explanation, or a reproducible necessary semantic/alias counterexample. Fix ordinary implementation bugs/bad fixtures before comparing; do not turn an unfinished wiring task into proof of inherent complexity.
